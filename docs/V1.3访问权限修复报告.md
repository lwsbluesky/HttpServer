# V1.3 本机目录选择与 guest 页面修复

日期：2026-11-13。修复对象为当前 V1.3.0.0 候选版。

## 问题与修复

1. **服务主机使用局域网 IP 访问时，无法浏览选择共享文件夹。** 原实现只将 `127.0.0.1` 和 `::1` 识别为本机；浏览器打开本机局域网 IP 时，请求来源也可能是局域网地址。现通过回环地址、本机地址解析和路由源地址核验来识别本机。接口继续要求管理员身份。不能仅因为来源是私有网段就允许触发服务主机上的窗口，也不使用浏览器提供的 Host/X-Forwarded-For 作为本机证明。
2. **guest 已有浏览/下载权限，登录后却出现“需要管理员权限”。** 可复现路径为打开或保留 `/manageCenter` 后登录 guest。前端原来保留管理页状态并请求管理员接口。现根据登录用户角色校验页面状态，普通用户自动回到 `/files`，清楚说明浏览/下载权限不包含管理权限。后端管理员接口仍拒绝 guest；文件接口按共享目录 ACL 授权。

## 验证结果

- 完整 pytest 回归：**77 通过、0 失败、1 跳过**；跳过项为当前 Windows 进程无法创建符号链接，Junction 回归通过。
- 本机地址单元测试：回环、本机局域网路由源地址识别通过；其他局域网客户端不被误认为本机。
- 选择文件夹接口：测试替身模拟 Windows 文件夹窗口，本机局域网地址可以进入选择流程，远程地址被拒绝。本轮没有人工实点原生 Windows 目录窗口。
- guest 文件 API：授权目录浏览、文件下载通过；管理接口仍返回 403，权限没有扩大。
- Microsoft Edge 实测：guest 登录、直接打开 `/manageCenter` 自动返回 `/files`、显示文件和真实下载通过；11 个浏览器流程完成，JavaScript 页面异常为 0。
- 修复后源码独立进程短测 30.17 秒，600 次普通请求均 200，P95 53.8 ms；源码/EXE 均验证两个目录压缩与 50 个普通请求并发时的正常响应或明确繁忙。
- 修复版 EXE 重新构建并运行测试：208 次普通请求均 200；实际重启后旧令牌失效、配置保留；临时文件残留 0。
- 本次是问题回归和短时运行检查，不能替代 72 小时真实长稳验收。

## 使用方式

停止旧 HttpServer 进程，备份数据目录，使用项目 `dist/v1.3/HttpServer.exe` 修复版启动。刷新网页并重新登录。服务主机上使用 `http://localhost:端口` 或本机局域网 IP 均可进入管理员目录选择；真正的远程设备仍须手工填写服务主机上的目录路径。

源码变更会随重新打包进入 EXE；仅刷新浏览器不能更新旧 EXE 中的后端代码。本轮未发布 GitHub Release。

完整测试报告见 [V1.3测试报告.md](V1.3测试报告.md)，原始回归结果见 [api-tests.xml](test-evidence-v1.3/api-tests.xml)。
